paddeck — scratchpad switcher

A graphical way to switch Umbriel scratchpads: see which windows each one holds, look at their real contents, then show, hide or jump to them with a keystroke. Open, act, close — no mouse required.

1. What it can do for you

Umbriel's scratchpad feature lets you tuck windows away and bring them back when needed. But normally you have to rely on memory: what exactly is in each scratchpad?

This tool exists for that — a panel built purely for switching:

👀 See what's inside

Every window gets a live thumbnail. Even when a window is tucked away in a scratchpad and invisible on screen, you can see its contents.

⌨️ Keyboard only

Move up and down, toggle with space, jump with enter. Your hands never leave the keyboard.

🪟 Switch a whole scratchpad

Bring all of a scratchpad's windows on screen at once, or tuck them all away. Their positions are remembered.

🔒 Read-only

It reads your Umbriel configuration and never modifies any of your files.

💡

The most useful part: windows in a scratchpad are invisible in normal use. With thumbnails, the terminals, browsers and editors you parked there are all visible at a glance.

2. Getting started

Step 1: check that it is installed

Run the following in a terminal. If it prints a version number, you are good to go:

paddeck --version

If you get “command not found”, ask whoever installed it (or do it yourself) to run:

meson setup build
ninja -C build
sudo ninja -C build install

Step 2: bind a shortcut ★

This is the only required step. Open Umbriel's keybind configuration, ~/.config/umbriel/binds.toml, and add one line: 

[keybinds]
"Mod+S" = "spawn:paddeck"

You can replace "Mod+S" with any combination you like. After saving, let Umbriel reload its configuration (in most cases pressing a key or reloading the config is enough).

Step 3: open the panel

Press the shortcut you just set: a translucent backdrop and a panel appear in the centre of the screen. Press the same shortcut again to hide it.

There are two more ways to close the panel:

  • Press Esc;
  • click the dark area outside the panel. (Clicks inside the panel do not close it.)
ℹ️

While the panel is open it captures the keyboard, so your keystrokes never leak to windows behind it. Once it closes, the keyboard returns to the previously focused window immediately.

3. A tour of the interface

  • 1Title bar: the panel name, with the connection status on the right.
  • 2Selected scratchpad: its border and name light up. Every key acts on it, so make sure you know which one it is.
  • 3Window preview: a live thumbnail of the window contents, with the title and app on the line below.
  • 4Status badge: visible / partly visible / hidden / empty — the scratchpad's current state at a glance.
  • 5Key legend: always visible, so you can glance down whenever you forget a key.

How to read the status badges

BadgeMeaning
visibleAll windows in this scratchpad are on screen.
partly visibleOnly some members are on screen (for example you revealed one of them with h l).
hiddenAll windows are tucked into the scratchpad; none are on screen.
emptyNo windows yet. If the config specifies a command to run when empty, toggling it launches that program.
implicitThis is Umbriel's default scratchpad, not one you created.

Individual window cards may also show a small badge in their top-left corner:

BadgeMeaning
focusedThis is the window currently in use.
visibleThe window is on screen (not tucked away).
urgentThe window is requesting attention (for example a terminal bell or a new message).

4. Keyboard reference

Once the panel is open, the keyboard belongs to it. Every action applies to the currently selected scratchpad; use j k to change the selection.

KeyAction
j / k Move down / up one scratchpad. Same as ↓ ↑ and Tab / Shift+Tab. Wraps around at either end.
Space Toggle the selected scratchpad: reveal it if hidden, tuck it away if visible. All of its windows move together and their original workspace positions are remembered.
h / l Reveal only the previous / next member window of the selected scratchpad. Same as ← →. Useful when there are many windows and you do not want them all at once.
Enter Jump to a window in the selected scratchpad (preferring the one in use) and close the panel, so you can get straight to work.
1 … 9 Jump straight to the n-th scratchpad and toggle it immediately — no need to move the selection first.
Home / End Jump to the first / last scratchpad.
Esc Close the panel.
💡

The three keys that cover most cases: j k to find the target, Space to show / hide it, Esc to leave. Enter means “switch to it and close the panel”, which is what you want when you are about to use the window right away.

Prefer the mouse?

  • Click a scratchpad card — select it (same as j k).
  • Click a window preview — focus that window and close the panel (same as Enter).
  • Click the dark area outside the panel — close the panel.

5. Window previews (thumbnails)

Every window in the panel is a thumbnail whose image is taken live from the compositor — not an icon, not a screenshot file.

✨

Windows tucked into a scratchpad can be previewed too. This is the biggest difference from an ordinary taskbar: those “invisible” windows are no longer a black box.

A few notes about the previews

  • Refresh rate: while the panel is open the image is updated roughly every 4 seconds, so it stays recent.
  • Power: capture stops the moment the panel closes, using no resources at all.
  • Aspect ratio: windows of different shapes are scaled down proportionally and centred, which may leave blank space around them. That is normal (nothing is cropped).
  • Right after opening: the first frame takes a second or two; during that time the tile shows the app's initials (for example GC), then turns into the image.
  • When capture is unavailable: the tile keeps showing the initials. This affects no functionality — switching and focusing still work.

6. Where scratchpads come from

Scratchpads live in Umbriel's own configuration, usually ~/.config/umbriel/config.toml. This tool only reads it; there is no create / delete / edit entry point in the UI — to add or remove one, edit the configuration file.

A minimal example:

# ~/.config/umbriel/config.toml
[[scratchpad]]
name = "work"

[[scratchpad]]
name = "media"
spawn_when_empty = "spotify"   # toggling it while empty launches this program

[[scratchpad]]
name = "notes"

name is what the panel displays. spawn_when_empty is optional: when set, toggling this scratchpad while it is still empty launches the given command — a handy one-key way to summon a frequently used program.

⚠️

Note: as soon as a named scratchpad exists, Umbriel removes the implicit default scratchpad. Windows that were parked in it return to their saved positions (nothing is lost).

The configuration can also be split across files and pulled in with [include]; the panel reads those too (it does not care about comments or formatting). 

[include]
files = ["binds.toml", "scratchpads.toml"]

Recommended: make scratchpad windows a consistent size ★

Consider adding this snippet. It makes any window that enters a scratchpad resize to 90% × 90% of the output's usable area (bars and other exclusive zones already excluded) and centre itself, regardless of the application — no per-application rules needed: 

# ~/.config/umbriel/config.toml
[animation.scratchpad]
scale = 0.9        # 0.1–1.0; 0 keeps the window's original size and position

A few things to keep in mind:

  • Windows entering a scratchpad are made floating automatically, so default_floating = true is not needed.
  • Precedence is fullscreen > maximize > scale; leave the first two at false (their default) for scale to apply.
  • There is a 100px floor. The value is computed once, when a window enters the scratchpad; after changing the configuration, windows already in a scratchpad must be taken out and put back in to pick up the new size.
⚠️

Do not try to achieve the same with a window rule — the following does not work: 

# ✗ invalid
[[window_rule]]
match.is_scratchpad = true
default_floating = true
default_floating_size = { width = 0.9, height = 0.9 }

Because default_floating / default_floating_size are open-time settings: they are resolved once when the window opens, and at that moment it is not in a scratchpad yet, so match.is_scratchpad can never match.

match.is_scratchpad only applies to runtime properties such as opacity, blur and border_color_focused: 

# ✓ valid: every window in a scratchpad becomes slightly translucent
[[window_rule]]
match.is_scratchpad = true
opacity = 0.9

7. Tips

  • Use it as a scratchpad monitor. Open it with Mod+S, glance, press Esc — two seconds to confirm that the windows you tucked away are still there.
  • Use the number keys for one-step access. Remember the index of the scratchpads you use most, then press 1–9 right after opening to toggle them without selecting first.
  • Reveal members one by one when there are many. h l reveals a single member, which is tidier than bringing out the whole group and picking.
  • Jump straight there once you have found it. Enter focuses the window and closes the panel — no need for Esc.
  • The panel follows your theme. Colours and corner radius come from your current Umbriel theme.
  • Give scratchpad windows a consistent size. Add [animation.scratchpad] with scale = 0.9 to your Umbriel configuration and any window entering a scratchpad becomes 90% × 90% and centred; see section 6.
ℹ️

No restart needed after changing the configuration: the panel re-reads it every time it opens.

8. FAQ

I press the key and nothing happens — the panel does not appear?

Check, in order:

  • Whether the shortcut is correct (the [keybinds] section in ~/.config/umbriel/binds.toml).
  • Whether Umbriel reloaded its configuration after the change.
  • Whether running paddeck directly in a terminal opens the panel.
Tiles keep showing initials instead of images?

This means the compositor on this machine does not provide the per-window capture protocols, or the window has not been rendered yet. The panel degrades to the “initials” style, and switching and focusing are unaffected. If the protocols are missing entirely, the bottom of the panel shows “Window previews are unavailable on this compositor.”.

A window is missing from the panel?

The panel only lists windows that live in a scratchpad. Ordinary windows on the desktop do not appear here — that is exactly what a scratchpad switcher is for.

After pressing Space, several windows appeared at once?

That is expected: showing a scratchpad reveals all of its members together. If you want them one at a time, use h l.

I want to create a scratchpad, but there is no entry point in the UI?

That is intentional: this tool only switches and does not touch the configuration. Add a [[scratchpad]] block to ~/.config/umbriel/config.toml as shown in section 6, then open the panel and it will be there.

Will it damage my configuration file?

No. It opens the configuration read-only and writes no files while running — not even temporary ones.

The panel swallows the keyboard while it is open?

Yes, by design: that way your keystrokes do not accidentally reach the windows behind it. After you close it with Esc or a click outside, the keyboard returns to the previous window immediately.

The top right shows ○ reconnecting…?

Umbriel is not running, or the communication socket is temporarily unavailable. The panel retries every second and switches back to ● connected once it recovers — no restart needed.

A red message appeared at the bottom?

The last action failed and the message explains why (for example a wrong scratchpad name). A failure does not stop you from using the panel.

9. Advanced: command line

Day-to-day use does not need the command line, but it is useful in scripts and for troubleshooting.

paddeck [options]

  -c, --config <path>   use the given Umbriel config instead of the default search
      --socket <path>   override the IPC socket (default: $UMBRIEL_SOCKET)
      --window          open a normal window instead of the full-screen overlay
      --dump            print every scratchpad and its windows as text, then exit
  -h, --help            show help
  -v, --version         show version

See the list without opening the UI:

$ paddeck --dump
config: /home/me/.config/umbriel/config.toml
loaded: 6 file(s)

[default] (implicit)  1 window(s), 0 visible
    hidden   kitty                ~

[work]  2 window(s), 2 visible
    visible  foot                 logs
    focused  kitty                editor

The visible / focused / hidden marker in front of each window shows whether it is currently on screen or tucked away.

ℹ️

--window opens a normal window instead of the overlay, which is handy for trying it on another compositor or for debugging.

10. Troubleshooting

  1. Check the bottom of the panel first. When an action fails, the reason is shown right there.
  2. Use --dump to see the raw data. paddeck --dump prints every scratchpad and window the tool sees, which makes it easy to tell whether the configuration took effect.
  3. No previews? That is a normal degradation and does not affect functionality. To confirm, run paddeck directly in a terminal and watch its output.
  4. A scratchpad is missing from the panel? Check that config.toml contains a [[scratchpad]] block, that name is spelled correctly, and that the panel was opened after the configuration change.
  5. The panel says “No scratchpads are configured.”? The configuration has no named scratchpad and no windows are currently tucked away. Add a [[scratchpad]] as shown in section 6.
