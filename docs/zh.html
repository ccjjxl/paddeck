paddeck —— 暂存区切换器

一个图形界面，用来切换 Umbriel 的 scratchpad（暂存区）： 看到每个暂存区里存着哪些窗口、它们的真实画面， 然后用键盘一键显示、隐藏或跳过去。呼出、操作、关闭，全程不用鼠标。

1. 它能帮你做什么

Umbriel 的 scratchpad 可以把窗口“收起来”暂存，需要时再拿出来。 但平时你只能靠记忆：哪个暂存区里到底放着什么？

这个工具就是为这件事做的 —— 一个纯粹用来切换的面板：

👀 看见内容

每个窗口显示真实画面缩略图。即使窗口正被收在暂存区里、屏幕上看不见，也能看到它的内容。

⌨️ 全键盘操作

上下选、空格切换、回车跳过去。手不用离开键盘。

🪟 切换整个暂存区

一次让一个暂存区的所有窗口出现或收起，原来的位置都记着。

🔒 只读，不改配置

它只读取你的 Umbriel 配置，永远不会改写你的任何文件。

💡

最实用的一点：暂存区里的窗口是“隐身”的，你平时看不到它们。 有了缩略图，你收起来的终端、浏览器、编辑器现在都一目了然。

2. 开始使用

第一步：确认已经安装

在终端里执行下面这行，如果有版本号输出，就说明已经装好了：

paddeck --version

如果提示“命令未找到”，请让安装者（或你自己）执行：

meson setup build
ninja -C build
sudo ninja -C build install

第二步：给它绑一个快捷键 ★

这是唯一必须做的一步。打开 Umbriel 的快捷键配置 ~/.config/umbriel/binds.toml，加入一行： 

[keybinds]
"Mod+S" = "spawn:paddeck"

键位 "Mod+S" 可以换成你喜欢的任意组合。 保存后需要让 Umbriel 重新读取配置（多数情况下按一下快捷键或重载配置即可生效）。

第三步：呼出面板

按下你刚设置的快捷键，屏幕中央会出现一个半透明遮罩 + 面板。 再按一次同样的快捷键，面板就会收起。

关闭面板还有两种方式：

  • 按 Esc；
  • 用鼠标点击面板之外的暗色区域。（点面板里面不会关闭）
ℹ️

面板打开时会独占键盘输入，所以你在里面按键不会跑到别的窗口去； 一旦关闭，键盘就立刻交还给原来的窗口。

3. 界面导览

  • 1标题栏：面板名称，右侧是连接状态。
  • 2选中的暂存区：边框和名称会亮起来。键盘操作全部作用在它身上，所以先看清它。
  • 3窗口画面：窗口内容的实时缩略图，底部一行是标题和应用名。
  • 4状态标签：显示中 / 部分显示 / 隐藏中 / 空，一眼看出这个暂存区现在的状态。
  • 5底部按键提示：常驻显示所有快捷键，忘了随时低头看一眼。

状态标签怎么看

标签含义
显示中这个暂存区的窗口全部显示在屏幕上。
部分显示只有一部分成员显示着（比如你用 h l 单独放出来了一个）。
隐藏中窗口都收在暂存区里，屏幕上没有。
空里面还没有窗口。若配置里写了“空的时候运行什么”，切换它就会启动那个程序。
implicit这是 Umbriel 默认的暂存区，不是你手动创建的。

单个窗口卡片左上角还可能出现小标签：

标签含义
focused这是当前正在使用的窗口。
visible窗口正显示在屏幕上（没有被收起）。
urgent窗口在请求注意（比如终端有提示音或新消息）。

4. 键盘操作速查

面板打开后，键盘就只属于它。所有操作都作用在当前选中的暂存区上， 用 j k 换选中项即可。

按键作用
j / k 向下 / 向上换一个暂存区。等价于 ↓ ↑、Tab / Shift+Tab。到头会绕回另一端。
Space 切换选中的暂存区：隐藏中的就显示出来，显示中的就收回去。它的所有窗口一起动作，原来的工作区位置都记着。
h / l 只让选中暂存区的上一个 / 下一个成员窗口显示出来。等价于 ← →。窗口多、不想一次全放出来时用。
Enter 跳到选中暂存区里的窗口（优先跳正在用的那个），并顺手关闭面板，直接开始干活。
1 … 9 直接跳到第 n 个暂存区，并立即切换它 —— 不用先移动选中项。
Home / End 跳到第一个 / 最后一个暂存区。
Esc 关闭面板。
💡

最省事的三个键： j k 找到目标，Space 显示 / 收起，Esc 退出。 Enter 则是“切过去并关掉面板”，适合找到了就立刻要用的情况。

也想用鼠标？

  • 点某个暂存区卡片 —— 选中它（和 j k 等效）。
  • 点某张窗口画面 —— 跳到那个窗口并关闭面板（和 Enter 等效）。
  • 点面板外的暗色区域 —— 关闭面板。

5. 窗口画面（缩略图）

面板里的每个窗口都是一张缩略图，画面实时取自合成器，不是图标也不是截图文件。

✨

被收进暂存区的窗口同样能看到画面。 这是它和普通任务栏最大的不同 —— 那些“隐身”的窗口不再是黑盒。

关于画面的几点说明

  • 刷新频率：面板打开时，画面大约每 4 秒更新一次，所以是新近的内容。
  • 省电：面板一关，抓取立刻停止，完全不占用资源。
  • 比例：不同形状的窗口会按比例缩小并居中，四周可能留出空白，这是正常的（不会裁掉内容）。
  • 刚打开时：第一帧画面需要一两秒才生成，这期间方格里显示应用名首字母（如 GC），稍等一下就会变成画面。
  • 抓不到画面时：方格里保持显示首字母。这种情况不影响任何操作 —— 切换、聚焦照常可用。

6. 暂存区从哪来

暂存区写在 Umbriel 自己的配置里，通常是 ~/.config/umbriel/config.toml。本工具只读它， 界面上没有新建 / 删除 / 编辑的入口 —— 想增删就改配置文件。

一个最简单的例子：

# ~/.config/umbriel/config.toml
[[scratchpad]]
name = "work"

[[scratchpad]]
name = "media"
spawn_when_empty = "spotify"   # 空的时候切换它，就启动这个程序

[[scratchpad]]
name = "notes"

name 就是面板里显示的名字； spawn_when_empty 是可选的，写了之后， 当这个暂存区还是空的时候切换它会启动指定的命令（方便一键叫出常用程序）。

⚠️

请注意：一旦有了具名暂存区，Umbriel 就会取消默认的 default 暂存区。 原来收在里面的窗口会回到它们各自保存的位置（不会丢失）。

配置也可以拆成多个文件，用 [include] 引进来， 面板同样能读到（包括配置里的注释和排版，它都原样不管）。 

[include]
files = ["binds.toml", "scratchpads.toml"]

推荐：让暂存区窗口统一大小 ★

建议加上这一段。它让任何窗口一进入暂存区就自动变成 输出可用区域（已扣除 bar 等独占区）的 90% × 90% 并居中， 不管是什么应用、也不需要按应用名写规则： 

# ~/.config/umbriel/config.toml
[animation.scratchpad]
scale = 0.9        # 0.1–1.0；0 表示保持窗口原有尺寸和位置

几个要点：

  • 窗口进入暂存区时本来就会自动浮动，所以不需要再写 default_floating = true。
  • 优先级是 fullscreen > maximize > scale， 想让 scale 生效，另外两项要保持 false（默认就是）。
  • 尺寸有 100px 下限；这个值只在窗口进入暂存区的那一刻计算一次， 修改配置后，已经躺在暂存区里的旧窗口需要取出来再放回去才会套用新尺寸。
⚠️

不要试图用窗口规则来达到同样效果 —— 下面这样写是不会生效的： 

# ✗ 无效
[[window_rule]]
match.is_scratchpad = true
default_floating = true
default_floating_size = { width = 0.9, height = 0.9 }

因为 default_floating / default_floating_size 属于开窗设置，只在窗口打开的那一刻结算一次，而那一刻窗口还不在暂存区里， match.is_scratchpad 永远匹配不上。

match.is_scratchpad 只对运行时状态类字段有效，例如 opacity、blur、border_color_focused： 

# ✓ 有效：暂存区里的窗口统一半透明
[[window_rule]]
match.is_scratchpad = true
opacity = 0.9

7. 小技巧

  • 把它当成“暂存区监视器”。 用 Mod+S 打开看一眼就 Esc， 两秒钟就能确认收起来的窗口都还在。
  • 用数字键一步到位。 常用暂存区记住它的序号， 呼出后按 1～9 直接切换，中间不用选。
  • 窗口多就逐个放。 用 h l 只放出一个成员， 比整组放出来再挑要清爽。
  • 找到了就直接跳。 Enter 会跳到窗口并关掉面板， 连 Esc 都省了。
  • 面板外观是跟随主题的。 颜色和圆角都取自你当前的 Umbriel 主题。
  • 让暂存区窗口统一大小。 在 Umbriel 配置里加 [animation.scratchpad] 与 scale = 0.9， 任何窗口进暂存区都会变成 90% × 90% 并居中，详见 第 6 节。
ℹ️

配置改动后不用重启工具：面板每次打开都会重新读一遍配置。

8. 常见问题

按键没反应，面板不出现？

依次检查：

  • 快捷键有没有写对（~/.config/umbriel/binds.toml 里的 [keybinds] 段落）。
  • 改完配置后 Umbriel 有没有重新加载。
  • 在终端里直接跑 paddeck 能不能打开面板。
方格里一直是首字母，没变成画面？

说明这台机器的合成器没有提供按窗口抓取画面所需的协议， 或者该窗口暂时没有被渲染过。面板会退化成“首字母”样式， 切换、聚焦这些功能都不受影响。 如果连协议都没有，底部会提示“Window previews are unavailable on this compositor.”。

面板里少了一个窗口？

面板只列出存在于暂存区里的窗口。普通显示在桌面上的窗口不会在这里出现 —— 这正是暂存区切换器的用途。

按了 Space 之后，屏幕上多了好几个窗口？

这是预期的：显示一个暂存区会把它的所有成员一起放出来。 如果只想一个个来，用 h l 逐个切换。

想新建一个暂存区，界面上找不到入口？

这是有意为之：本工具只做切换，不碰配置。 在 ~/.config/umbriel/config.toml 里按第 6 节的样子加一段 [[scratchpad]]，再打开面板就能看到它。

它会改坏我的配置文件吗？

不会。它只读配置，运行期间不写任何文件 —— 连临时文件都不会产生。

面板一打开，键盘就被它“吃”掉了？

是的，这是刻意设计：这样你在面板里的按键不会误发到后面的窗口。 按 Esc 或点面板外关闭后，键盘会立刻还给原来的窗口。

右上角显示 ○ 重连中…？

Umbriel 没在运行，或者通信接口暂时不通。面板会自动每秒重试， 恢复后会变回 ● 已连接，无需重启。

底部出现一条红色提示？

说明刚才那个操作失败了，提示文字就是原因（比如暂存区名字不对）。 失败不影响面板继续使用。

9. 进阶：命令行

日常使用不需要命令行，但它在脚本和排查问题时很有用。

paddeck [选项]

  -c, --config <路径>   指定 Umbriel 配置文件，而不是按默认顺序查找
      --socket <路径>   指定通信接口（默认 $UMBRIEL_SOCKET）
      --window          用普通窗口打开，而不是全屏覆盖层
      --dump            以纯文本打印所有暂存区及其窗口，然后退出
  -h, --help            显示帮助
  -v, --version         显示版本

不打开界面，直接看清单：

$ paddeck --dump
config: /home/me/.config/umbriel/config.toml
loaded: 6 file(s)

[default] (implicit)  1 window(s), 0 visible
    hidden   kitty                ~

[work]  2 window(s), 2 visible
    visible  foot                 logs
    focused  kitty                editor

每个窗口前的 visible / focused / hidden 表示它当前是显示还是被收起。

ℹ️

--window 会打开一个普通窗口而不是覆盖层， 适合在其它合成器上试用，或者调试。

10. 出问题了怎么办

  1. 先看面板底部的提示。 操作失败时这里会直接显示原因。
  2. 用 --dump 看原始数据。 paddeck --dump 会打印工具看到的全部暂存区与窗口， 方便对照是不是配置没生效。
  3. 没有画面？ 属于正常降级，功能不受影响；想确认的话， 在终端里直接运行 paddeck 观察输出。
  4. 暂存区没出现在面板里？ 确认 config.toml 里有 [[scratchpad]] 段、name 没写错， 并且面板是配置改完之后才打开的。
  5. 面板显示“No scratchpads are configured.”？ 配置里没有具名暂存区，而且当前也没有窗口被收起来。 按第 6 节加一个 [[scratchpad]] 即可。
